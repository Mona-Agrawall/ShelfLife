You are building a complete, working college project called "ShelfLife" inside the currently open workspace folder (DevOps). It is a pantry and expiry tracker with an automated CI/CD pipeline. This is for a Cloud and DevOps course whose rule is: every project must use AWS, Git, Jenkins, and at least one DevOps tool (I use Docker AND Terraform). The app is intentionally simple; the DevOps pipeline is what gets graded. Build everything end to end, run it, and fix anything that fails. Do not leave TODOs or stubs.

## 1. App (Flask + SQLite)
Create the app inside `app/`:
- `app/app.py` using an app factory `create_app(db_path=None)`. The DB path comes from the env var `DB_PATH` (default `data/shelflife.db`). Create the table automatically on startup.
- Table `items`: id, name, category, quantity (int), expiry_date (date), added_on.
- Pages (Jinja templates in `app/templates/`, clean responsive CSS in `app/static/style.css`, no JS frameworks):
  1. `/` Dashboard: counts of Expired, Expiring in 3 days, and Fresh items, plus a count per category.
  2. `/add` Form to add an item (name, category dropdown: Dairy, Vegetables, Fruits, Grains, Snacks, Beverages, Other; quantity; expiry date) with validation.
  3. `/expiring` Items expiring within the next 3 days, plus already-expired items highlighted in red.
  4. `/inventory` Full list sorted by expiry date with a Delete button (POST).
- `/health` returns JSON {"status": "ok"} (used by Docker healthcheck and the pipeline).
- Put the status logic in a pure function `get_status(expiry_date, today=None)` returning "expired", "expiring_soon" (0 to 3 days left), or "fresh". Make it unit-testable.
- Run with gunicorn on port 5000 in the container.

## 2. Tests
`tests/test_app.py` with pytest, at least 6 tests: get_status for expired, today, 3 days, 4 days; add item via POST; /health returns 200; delete item; the dashboard renders. Use a temp database so tests never touch real data. Add `pytest.ini` so tests run from the project root. Make Jenkins-friendly output with `--junitxml=test-results.xml`.

## 4. Terraform (folder `terraform/`)
Files: `main.tf`, `variables.tf`, `outputs.tf`, `versions.tf`, `terraform.tfvars.example`, `user_data_jenkins.sh`, `user_data_app.sh`.
- AWS provider, region variable (default us-east-1). Credentials come from the environment or the AWS CLI; never hardcode any.
- Look up the latest Ubuntu 22.04 AMI with a data source and use the default VPC.
- Generate the key pair with `tls_private_key` + `aws_key_pair`, and write the private key to `shelflife-key.pem` with `local_file` (file_permission 0400).
- Security group for Jenkins: 22 and 8080. Security group for the app server: 22 and 5000. Make the allowed CIDR a variable (default 0.0.0.0/0 with a comment advising to restrict it).
- Two EC2 instances:
  - `jenkins_server`: user_data installs Java 17, Jenkins (official apt repo), Docker, adds the `jenkins` user to the `docker` group, installs git, creates a 2 GB swap file, and enables and starts the services.
  - `app_server`: user_data installs Docker, adds the `ubuntu` user to the `docker` group, and enables the service.
- Variables: `instance_type` (default t3.small, with a comment saying t2.micro works on personal free tier only with swap), `instance_profile_name` (default "" ; set it to "LabInstanceProfile" on AWS Academy; use null when empty), `project_name` (default "shelflife"), `allowed_cidr`.
- Elastic IPs for both instances (so IPs survive restarts), with outputs for the Jenkins URL, the app URL, the SSH commands, and the public IPs.
- CloudWatch: a log group `/shelflife/app`, and a CPU utilization alarm (> 70% for 2 periods of 5 minutes) on the app server.
- Backend: use local state by default. Include a commented-out S3 backend block with instructions.
- Run `terraform fmt` and `terraform validate` (run `terraform init -backend=false` first). If terraform is not installed, say so clearly and double check the syntax by hand instead.

## 5. Jenkins
`Jenkinsfile` (declarative pipeline):
- Environment: DOCKERHUB_USER and IMAGE_NAME as variables at the top, credentials IDs `dockerhub-creds` (username/password) and `app-server-ssh` (SSH private key), and `APP_SERVER_IP` as a Jenkins environment variable or a pipeline parameter.
- Stages: Checkout → Install & Test (create a venv, pip install, run pytest with junit xml; publish with the `junit` step in post) → Build Docker Image (tags: BUILD_NUMBER and latest) → Push to Docker Hub → Deploy (using `sshagent`, SSH to the app server, `docker pull`, stop and remove the old container, run the new one with `-p 80:5000 -v shelflife-data:/data --restart unless-stopped`, optionally with `--log-driver=awslogs` commented out as an optional step) → Smoke Test (curl /health on the app server and fail the build if it is not 200).
- `post` section: success and failure messages, `docker image prune -f`.
- Make `dev` branch builds run Test and Build only, and `main` branch builds run the whole pipeline (use `when { branch 'main' }`, and mention in the README that this needs a Multibranch pipeline, with a simpler alternative of a normal pipeline job pointed at main).
- The deploy script should live in `scripts/deploy.sh`, and the Jenkinsfile should call it.
